# Kubernetes example

This Kustomize base is an example for a single-node MicroK8s cluster with `microk8s-hostpath` storage for the database, NFS for attachments and backups, Traefik in namespace `traefik`, and cert-manager with a ready `letsencrypt-prod` ClusterIssuer. Before applying it, replace the placeholder values with your own: the hostname `spunto.example.org` (`deployment.yaml`, `ingress.yaml`, `http-redirect.yaml`), the node name `node-1` and the time zone (`deployment.yaml`), and the NFS server `192.0.2.10` with its `/srv/nfs/spunto` export paths (`shared-storage.yaml`). This base includes a host-scoped HTTP ingress and namespace-scoped [RedirectScheme middleware](https://doc.traefik.io/traefik/reference/routing-configuration/http/middlewares/redirectscheme/) so the redirect is explicit without changing another application's routing. Its priority is 1, below cert-manager's more specific [HTTP01 solver route](https://cert-manager.io/docs/configuration/acme/http01/). Only the HTTPS ingress requests the certificate.

Render a local immutable image override without changing the base files or contacting the cluster:

```sh
python3 deploy/k8s/render-local.py 'spunto:m5-OPERATOR_CONTENT_FINGERPRINT' > /tmp/spunto-rendered.yaml
```

Replace the example image with the exact tag imported into your node's MicroK8s containerd. Tags must end in a 12–64 character lowercase hexadecimal content fingerprint; a `name@sha256:<64 hex>` reference is also accepted. The operator must verify the tag is bound to the reviewed image ID and not reuse it for different content. The helper accepts `kustomize` or `kubectl kustomize`, uses a temporary copy and renders only. The base placeholder cannot start without an imported image. Both base and override use `imagePullPolicy: Never`, so no Pod pulls an image from a registry. Import an amd64 image under the exact rendered reference before starting the workload. The image's dependency lockfiles and web bundle must match the reviewed source.

Provision owner authentication before exposing the ingress. Create `spunto-owner` separately, with an `owner_password_hash` key containing the output of interactive `spunto owner hash-password`. Keep the hash out of terminal output, Git, rendered manifests and logs; use a protected local file or the operator's SOPS workflow. The Secret is explicitly required and mounted read-only. A missing Secret prevents the Pod from starting; an unreadable or invalid Argon2id hash prevents the application from starting. Therefore this deployment has no unauthenticated setup takeover window. Kubernetes Secrets need the operator's normal at-rest/access protections. The public URL uses HTTPS, enabling secure login cookies and correct device pairing payloads; preserve the public Host through Traefik.

The operator supplies the imported immutable image reference, owner-hash Secret, DNS A/AAAA records pointing to the ingress, reachable public TCP 80/443, and a functioning HTTP01 issuer. Verify the Traefik CRD and namespace/pod selectors against the cluster before applying. No live deployment or cluster repository mutation is performed by the renderer. Start with a new, empty `spunto-data` PVC: never import the synthetic acceptance database, fixture libraries or `/tmp/spunto-m5-live` data. Keep one replica and `Recreate`; the store refuses a second process on its volume. The node selector keeps the imported image and node-local volume together. Monitor host disk capacity and the 5 GiB claim; hostpath does not provide a resilient storage quota or node failover. The database must never use NFS.

Startup/readiness use `/readyz`, with up to ten minutes for first startup; liveness uses `/healthz`. Requests are 20m CPU/96 MiB and limits 500m/512 MiB. Service links are disabled so Kubernetes cannot inject a `SPUNTO_PORT=tcp://…` value that collides with integer application configuration. The server runs as UID/GID 10001 with a read-only root, temporary writable `/tmp`, no service-account token or Linux capabilities. Network policies allow only Traefik ingress on TCP 8080, CoreDNS TCP/UDP 53 and the cluster's `app=ollama` pods on TCP 11434. They leave temporary cert-manager solver pods outside the application deny rule. Apply `ollama-ingress.yaml` separately in namespace `ollama`; the destination's existing deny policy also needs this allowance. No general HTTPS egress is granted to Spunto. Confirm the installed network plugin enforces these policies.

After an authorized deployment, verify the certificate becomes Ready and serves a valid chain, HTTP redirects to HTTPS, `/readyz` succeeds, password login sets a `Secure` session cookie, unauthenticated setup is closed, and authenticated device pairing issues an expiring one-use grant. `/mcp` remains on this same host and requires its bearer token. Never pass pairing codes or bearer credentials in URL queries.

The base mounts `spunto-backups` at `/backups` and `spunto-attachments` at `/attachments`, two static NFS PVs in separate export directories; the SQLite database stays on its local PVC. Claims advertise 20 GiB each but do not enforce a disk quota. Before deploying the base, create both directories owned by UID/GID 10001 with mode `0750`, export them to the node only with `rw,sync,no_subtree_check,root_squash`, and include them in your off-site backup. Probe the actual NFS mounts after reloading exports; directory existence alone does not prove access. A backup schedule alone does not establish coverage: verify a snapshot plus attachments through a recovery check. See [operations](../../docs/operations.md) for restore limits.

The example uses `gpt-oss:20b-cloud` for Ollama Cloud chat and local `embeddinggemma-2:270m` for embeddings. A local Ollama proxy does not make a cloud model local. Settings → AI lists the provider's available models and lets the space owner save a choice for each capability or restore the environment defaults. Embedding dimensions are checked against the served model, and a changed model builds a separate index. Transcription and vision stay unbound until an appropriate model is selected; selecting a capability does not widen a plugin's permissions.
