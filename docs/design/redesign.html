The same quiet notebook as design/mockups.html, rebuilt as a small core with everything else as a plugin. Plugins never draw their own screens: they fill a handful of fixed slots with the app's own parts, so a page with eighteen plugins on still reads like a page of notes. Read with 05-redesign-ux.md; the plugin mechanism is in 04-redesign.md. Sample notes are invented but realistic.

Core only, then the default set

On the left, a fresh install with no AI configured: the core and nothing else. On the right, the same notes once an AI provider is set and the four default plugins switch on (Label suggestions, Semantic search, Related notes, Ask your notes). The whole visible difference on the timeline is two lines of text. No new buttons, no new rail rows, no new colours.

A note and its furniture

From here on the instance has eighteen of its 25 plugins on. A link saved from Chrome shows every slot a note can carry: the suggestion line under the text, one plugin fact in the meta line, and the note panel, which is the right margin on the web and the "About this note" sheet on Android. Panel sections start closed and stay the way you leave them.

Commands live where commands already were

Plugins add verbs, never buttons. A plugin's commands appear in the ⌘K palette, the composer's / menu and the Android note action sheet, each with the plugin's name when it is not obvious from the verb. A spark marks every command that sends text to your model.

The daily slip and Review

Two shared places hold what does not belong under one note. The daily slip shows one older note a day at the top of the timeline (and on the widget). Review is one core screen for every proposal that needs a decision about more than one note: label merges, new labels for clusters, duplicate pairs, and notes still waiting for labels. Both have a budget of one: one slip a day, one line pointing to Review.

AI plugins at work

Answers appear where they were asked for, as a command result, and become notes only when the owner keeps them. Scheduled work, like the weekly digest, writes an ordinary note with a spark chip. Changes to the owner's own text, like Tidy, are always a diff to accept.

Settings → Plugins

One list of every installed plugin, grouped by what it helps with, one switch each. Under each name, a single grey line says what the plugin touches: for AI plugins, which capability it uses and exactly where your text goes. Switching one on shows that again as a short sheet before anything runs. There is no store: whoever runs the server installs plugins, and this page only switches them.

Three themes, light and dark

A theme is a pack of colour values and nothing else: type, spacing, shapes and motion are fixed, so plugin output can never look wrong in one theme and right in another. Carta is the original warm paper. Ardesia is cool slate with ink blue, for long sessions on bright screens. Salvia is pale sage with forest green, the softest of the three. Each text colour clears WCAG AA in both modes; the table at the end computes the ratios live from the same values the frames use.
