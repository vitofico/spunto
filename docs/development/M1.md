# M1 local handoff

M1 adds the core note service, REST API and authenticated MCP HTTP transport to the M0 server foundation. This document records implementation choices and local evidence; it does not amend the approved requirements/spec/design documents.

## Implementation boundaries

The shared service owns note writes, inline labels, folded keyword search, revision coalescing, stale-edit merging/conflicted copies, private-note filtering, provenance and Markdown export. REST and the seven core MCP tools use that service. MCP is stateless HTTP at `/mcp`, with three tools for read tokens and seven for write tokens, plus access-controlled `note://` resources. The MCP dependency/API version in the lockfile is the one this implementation and tests target.

Revision 1 is retained even when later edits coalesce. `source.url` stores a captured link separately from agent token provenance in `source.ref`. These are additive local implementation details, with tests defining the behavior; the approved `docs/01`–`05` remain unchanged.

The plugin host is M2. Web is M3. AI and semantic search are M4. Full Android UI, server sync endpoints, offline replica/outbox and production dictation are M5. `spikes/android` remains a throwaway diagnostic app, not a first client release. M0 checks needing the owner's phone and model-driven Claude access remain open where their spike reports say so.

## Run locally

```sh
cd server
uv sync --locked
uv run pytest
uv run ruff check .
uv run ruff format --check .
SPUNTO_PUBLIC_URL=http://localhost:8080 SPUNTO_DATA_DIR=/tmp/spunto-dev \
  SPUNTO_LOG_FORMAT=text uv run spunto serve
```

Use [API](../api.md) for versioned request contracts and [operations](../operations.md) for snapshots, restore and local Kubernetes preparation. Keep logs free of note/search text and credentials. Do not deploy the `dev-local` manifest or publish the branch as part of this local work.
