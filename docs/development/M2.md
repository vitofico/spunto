# M2 local handoff

M2 is implemented locally. The owner authorized continuation after M1 and selected fixture-only Blinko validation. No commits, pushes, pull requests, releases, cluster actions or live-library imports were performed. The approved requirements/spec/design documents were not edited to match implementation; their pre-existing work remains.

## Implemented

- Schema 3 adds core-owned plugin settings, KV/documents, suggestions, annotations, search text and persistent jobs. Loader validation precedes Python import; only bundled first-party modules load, with API 0.4. Third-party loading/frozen API is M8.
- Lifecycle uses serialized transitions and context generations. Disable pauses jobs, removes routes/tools and invalidates old handles permanently. Environment pins reject unknown IDs. Data migrations require a fresh pre-migration snapshot and fail the plugin safely.
- The sleeping worker handles coalescing, five-minute leases, singleton crash recovery, retries, circuit failures, schedules and core backups/retention. Reserved host counters cannot be rewritten through plugin storage. Owner-started queued imports preserve their uncapped origin; agent job enqueue is unavailable in M2.
- Generation-bound note/attachment adapters enforce caller scope and private/external visibility, provenance, owner adoption, update-own protection, creation/output budgets and content-addressed files. Synced output deletes leave tombstones. Disabled plugin search text is reindexed away.
- Guarded fetch validates every resolved address and redirect, connects to the checked IP while preserving Host/TLS SNI/certificate verification, blocks local/metadata/self destinations, and bounds time and identity response bytes. Non-identity compression is rejected before decoding. Debug transport logs cannot disclose response headers or URLs. Only destination-host counts enter status.
- REST exposes management, generated public settings, commands, enabled-only routes/views, ETags, preferences and change waits. Seven suggestion actions apply atomically under the deciding credential; linked-note visibility is rechecked before serialization and decisions. Markdown is sanitized and attachment downloads enforce note visibility and download active formats.
- MCP dynamically discovers enabled tools per token, supports hiding, carries declared safety/retry hints, fences free-text plugin output and limits answers. Malformed plugin tool schemas cannot disrupt core discovery.
- All four plugins default off: `tasks` derives checkbox progress; `agent-inbox` tracks PAT edits and reviewed membership; `resurface` writes one daily slip using `TZ`; `blinko-import` supports paged dry runs, queued REST imports and stopped-server CLI imports. Import reruns preserve owner edits/private notes, source times/state and attachment links while leaving code examples unchanged.
- Local CI configuration adds Renovate, CodeQL, Trivy and a 150 MB compressed image budget per architecture. No hosted workflow was invoked.
