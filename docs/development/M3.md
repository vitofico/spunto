# M3: web client

M3 is complete locally, following the owner's instruction to use subagents and keep everything off GitHub. The approved requirements, specification and design documents were preserved. No commits, pushes, pull requests, releases, deployments or real Blinko imports were made.

## Implemented

- React 19, Vite and strict TypeScript; TanStack Query, wouter and generated OpenAPI types with openapi-fetch. Core capture, note, history, search, label, archive, trash, login/setup and keyboard-command screens.
- Durable owner-scoped browser drafts. Capture publishes on explicit Save. Existing notes autosave after five idle seconds, every minute during typing and on leaving. Queued submissions retain their payload and idempotency key across reloads and sign-in. Acknowledgements preserve later typing; conflict recovery shows the saved text and requires an explicit reviewed save.
- Authenticated multipart image uploads and content-addressed downloads, native checkbox controls with trusted UTF-16 source offsets, and clickable inline labels rendered by the server. Markdown code, escaped labels, existing links and references remain intact.
- Closed seven-component plugin vocabulary, all slots, Review, generated public settings, permission sheets, plugin switches/order/hiding and deletion counts. Daily slips load independently of the timeline page. All four M2 plugins default off; the core remains a finished app with no empty plugin chrome.
- Carta, Ardesia and Salvia in light/dark/system modes; instance themes, separate device overrides, reading face and text size. The production index receives validated cookie attributes before painting. Open browsers follow instance theme changes while keeping device overrides. Fonts are self-hosted with OFL licenses.
- Devices, password management, one-time access tokens, pasteable agent setup, export/trash/import controls and status. AI remains unconfigured in M3; third-party plugin installation remains M8.
- Read-only SPA hosting with immutable hashed assets, missing-asset/API boundaries, safe fallback routes and CSP. A pinned Node build stage packages the client into the Python image; Node is absent from the runtime. Docker builds now use the repository root and `-f server/Dockerfile`.

## Local use and handoff

The current preview is `http://127.0.0.1:18083`, using disposable synthetic data in `/tmp/spunto-m3-live/data` and the test password `browser acceptance password`. Its source server process and built `web/dist` serve the final implementation. This is separate from any owner library.

Prerequisites are Python 3.14/uv and Node 26/pnpm 12.11.2. The host's older global pnpm does not understand the new lockfile format; use the pinned version, for example `npx --yes pnpm@12.11.2 <command>`. Normal development and production commands are in the root README. Relevant checks:

```sh
cd server
uv run ruff check .
uv run ruff format --check .
uv run pytest
cd ../web
npx --yes pnpm@12.11.2 typecheck
npx --yes pnpm@12.11.2 test
npx --yes pnpm@12.11.2 format:check
npx --yes pnpm@12.11.2 build
```
