# M5: native Android and offline sync

The M5 implementation is developed locally with subagents and tested on the retained Android emulator. Git changes remain local: no commits, pushes, pull requests or GitHub releases. The owner subsequently authorized HTTPS/authenticated deployment to the existing theficos cluster at `spunto.theficos.dedyn.io`. Acceptance uses synthetic notes, images, pairing credentials and speech fixtures. Physical-phone acceptance remains a separate release gate.

## Scope and ownership

- Server: device authentication, one-use QR pairing, ordered idempotent sync push, paged pull with plugin output and tombstones, restore reconciliation and shared scenario fixtures.
- Android data: Kotlin conformance model, Room replica and FTS4 search, transactional outbox and drafts, secure authentication, background/foreground sync and image uploads.
- Android app: native Compose screens, cached plugin vocabulary and views, themes, capture entry points, dictation, widget and tiles.
- Integration: web pairing, emulator scenarios and screenshots, local builds and budgets, regression checks and independent review.

The approved requirements, specification and design documents 01–05 are preserved. Baseline evidence for the completed M4 source and unchanged Git state is retained in `/tmp/spunto-m5-baseline/`.

The real SQLite/ASGI synthetic 10,000-note pull took 2.229 seconds across 20 pages (6,597,407 JSON bytes, 635,418 gzip bytes). This measures server serialization and paging, not Android/Wi-Fi synchronization. Evidence: `/tmp/spunto-m5-server/benchmark.json`.

Android CI now starts a disposable hardened server with a temporary database, runs the real-server Kotlin integration with an explicit local URL, gates all six Android libraries and app lint, and executes native tests on API 35. This workflow was checked and independently reviewed locally; it has not run on GitHub.

The actual native Ask check exposed a request that exceeded the ordinary sync deadline and left “Reading your notes…” visible after the error. The correction gives only the Ask command a bounded 240-second deadline, clears progress in `finally`, propagates cancellation and permits retry. Independent review then reproduced cancellation failing to close a call after its response headers arrived. The shared request/upload adapter now consumes and closes the complete response before resuming its cancellable continuation. Four coroutine and four network regressions cover these paths, including a delayed-body test that signals before the blocked read; both source deltas passed independent review. The separate compiled delayed-body probe confirms actual call cancellation and job completion in 12 ms after the fix.

## Known verification boundaries

The emulator supplements the reference-phone checks; performance figures from an emulator do not establish the Pixel 6a-class targets on physical hardware. Real Italian/English speech in airplane mode, Gboard/SwiftKey handoff and physical TalkBack checks retain their hardware requirement. Scripted engines verify dictation state and transcript preservation independently of the installed speech service.

Capture intent checks used an Android shell sender. The actual share picker and return to its calling app, camera scanning, launcher/widget surfaces and accessibility at enlarged text still need manual verification. The QR image was decoded by actual ZXing and its JSON was consumed by native pairing. Composer-clear acknowledgement and search verify the unique new note outside the local-save trace, so the measured trace does not establish below-viewport card-render timing.

The server is deployed with a valid HTTPS certificate, HTTP redirect, required owner-password hash, one replica and restricted network access. The production database began empty; temporary public validation credentials were revoked and no fixtures were imported. The local Ollama fixture passed chat and embedding health checks with `qwen3.8:27b-mlx` and `embeddinggemma`; production has no AI provider configured yet. Production snapshots currently share the database PVC, so they do not provide recovery after loss of that disk/node.

The installable APK and signing pipeline remain local; the owner key is stored outside the repository in a private directory. No GitHub publication is authorized or performed. Physical-phone acceptance still governs an Android release.
