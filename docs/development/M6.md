# M6: organization and development plugins

The owner authorized finishing M6 through M8, fixing gaps found during the full-product audit, and adding two bolder colour themes. Git changes remain local. Synthetic fixtures are the only import and AI acceptance data. M5 evidence remains in `M5.md`; it does not establish physical-phone performance or speech acceptance.

This is the detailed specification for the eight M6 plugins required by 02 §2.19 and §16. Implementation and verification are in progress. Every plugin defaults off. Contributions use the existing vocabulary and host budgets, and all AI text passes through the gateway's data delimiters. No plugin silently replaces the owner's text, bypasses a disabled generation, or reads private or machine-written notes into an AI route.

| Plugin | Trigger and bounded input | Output and owner control |
|---|---|---|
| `title-summary` | Changed eligible notes of at least 300 words; one bounded note per job | Closed structured title and summary; title becomes a `set_title` suggestion and summary a stored collapsed panel. It never creates a note. |
| `tidy` | Sixty seconds after saving a dictated note, identified by Android source ref `dictation`; explicit command for another eligible note | One bounded `replace_body` proposal. The core diff, ordinary revision history and explicit acceptance own the edit. Rejected unchanged text is not repeatedly proposed. |
| `duplicates` | Eligible saved notes and their indexed neighbours; embeddings only | Bounded candidate pairs become `merge_pair` Review proposals. Comparing and merging are core owner actions. Rejected pairs are remembered; no chat call or automatic merge. |
| `label-gardener` | Weekly pass over a bounded eligible vocabulary and unlabeled notes | At most three global `label_change` proposals in the week, sharing the host budget. Rename/merge uses `{old,new}`; a new label for a cluster uses `{new,note_ids}` with at most ten notes. Dismissed fingerprints do not recur. |
| `links` | Saved Markdown links between notes; explicit Link to note command | Stored Backlinks panel and an append-link suggestion. Core acceptance owns the body edit. Backlinks from generated develop/translate follow-ups are ordinary links. |
| `digest` | Weekly owner-selected day/time, with excluded labels and a minimum activity threshold; explicit command | A cited machine-written note, Digests view and `digest_latest` MCP tool. Quiet weeks create nothing. The same week/request creates at most one result. Bounded coverage is stated when an eligible window is truncated. |
| `develop` | Explicit command on an eligible note plus at most five eligible neighbours | A cited, linked machine-written follow-up with questions, next steps and angles. The seed note is unchanged. Repeated identical request IDs return the existing result. |
| `translate` | Explicit Italian-to-English or English-to-Italian command, bounded eligible note | A command-result preview with an explicit Save action that creates a linked machine-written note. The original stays unchanged. Saving rechecks the original version and uses an idempotent request. |

The manifest table in 02 §2.19 binds each plugin's slots, permissions and defaults. Enabling an AI plugin without its required binding leaves it Waiting. No contributions appear while Waiting or disabled. Panel sections start collapsed and no plugin adds a bespoke toolbar, notification or client code.

The host adds a bounded job delay for tidy, scoped suggestion history for remembering dismissals, and transactional version guards for annotations and citation-based creation. These are additive changes toward plugin API `0.9`; legacy bundled `0.4` manifests continue loading during migration. Models never choose the borrowed note versions: the host captures and compares them. A stale note, changed privacy/provenance, disabled generation, provider failure or invalid response leaves no new annotation, suggestion or generated note.

Cluster label proposals use the existing global Review path. The host records all selected note versions, and acceptance atomically rechecks eligibility, unlabeled state and every version before appending the label. Impact preview returns a count using the session-only core endpoint. There is no device/offline global label mutation or agent authority expansion.
