# Configured attachment upload limit

The approved `SPUNTO_MAX_UPLOAD_MB` setting now controls attachment ingress and the AI gateway's image/audio byte checks. Its default is 20 MB, where one MB is exactly 1,000,000 bytes, preserving the attachment store's existing decimal-byte convention. Valid values are whole integers from 1 through 1000; booleans, fractions and invalid environment values are refused with the variable named. Configuration remains environment-only.

The public `/api/v1/meta` response adds the integer `max_upload_bytes` so clients can validate a selected file against this instance's limit. Older servers without the fact retain the native client's conservative 5 MB fallback. Multipart requests still contain one file and no additional fields. The file itself may be exactly the configured byte count; an extra byte is refused. A separate 65,536-byte allowance covers multipart framing. Declared length and streamed bytes are bounded before file storage; overflow stops consumption and closes partially spooled files.

The core attachment writer applies the same limit to plugin writes. Image signature detection, MIME handling, attachment download disposition and SHA-256 byte addressing are unchanged. Generic `audio/ogg`/`audio/opus` content is already accepted as a download attachment; this change adds no recording format or duration metadata. The voice-memos plugin reads duration from its Ogg Opus or WAV container, and the gateway retains its one-hour duration limit. Native capture and recording controls remain separately owned work.

Importer archive/member budgets remain independent: Markdown keeps its 5 MB asset ceiling and preflights the effective minimum of that ceiling and the instance limit across all referenced assets before any note writes. Increasing the public attachment limit does not increase import budgets. The Blinko importer described in earlier checks has since been [removed](../decisions/2026-10-19-remove-blinko.md).

Acceptance uses synthetic files and streams on real SQLite. Coverage includes the default 20,000,000-byte boundary, smaller configured boundaries, one-byte overflow, chunked uploads without Content-Length, early overflow termination and partial-spool cleanup, malformed/oversized declared lengths, MIME/download safety, public metadata facts, shared image/audio gateway checks and importer preflight/reporting. No network accounts, production data, emulator or Gradle actions are part of this check. Evidence lives in `/tmp/spunto-upload-limit`; the final source manifest and gate counts are recorded there after validation.
